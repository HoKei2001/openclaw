# Software Patent Claims Explained

**Published**: 2016-11-25

## Overview

This instructional video from Inventor's Quick Tips uses a voice assistant (like Siri) as a practical example to teach the fundamentals of drafting software patent claims. The core lesson centers on two analytical frameworks: actor analysis (who performs each step of the claim) and location analysis (where each step is performed). The ideal software patent claim has a single actor performing all steps in a single location, because patent infringement requires showing that one party performed all steps of a claim — multiple actors means multiple defendants, which weakens enforceability.

Starting with a four-step claim covering a voice assistant workflow (user speaks into phone, phone sends audio to server, server converts audio to text, server returns text to phone), the video demonstrates how this claim spans three actors (user, phone/client, server) and two locations (Canada for the user, U.S. for the server). This is problematic for enforcement. The refactored version eliminates the user-action step ("uttering a phrase") and flips the remaining client-side steps to server perspective — resulting in a three-step claim where the server is the sole actor performing all steps in a single U.S. location.

The video then outlines best practices for software claims: always try to draft separate claims from both the client perspective and the server perspective in client-server architectures, and always draft three types of claims for software — method claims (what the software does), device/system claims (the hardware running it), and computer-readable medium claims (the software as a stored physical object on a CD-ROM, USB stick, etc.). This three-form approach maximizes the scope of patent protection.

## Key Takeaways

- Actor analysis: identify who performs each step of the claim — ideally one actor performs all steps to maximize enforceability
- Location analysis: all steps should ideally occur in the same jurisdiction for clean enforcement
- Flipping from the client's perspective to the server's perspective often reduces actors and consolidates location
- Draft claims from both client and server perspectives in client-server architectures
- Three types of claims are standard for software patents: method claims, device/system claims, and computer-readable medium claims
- Removing unnecessary steps (like "uttering a phrase") that introduce extra actors can strengthen a claim
- These principles apply beyond software — single actor/single location is a general best practice for all patent claims

## Best For

Patent practitioners, software developers, and engineering students who want a concrete, example-driven introduction to drafting effective software patent claims.
