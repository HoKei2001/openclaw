## Overview

This video by patent attorney James Yang provides practical tips for writing software patent applications that can survive the USPTO's increasingly strict scrutiny. The discussion centers on the challenges created by Section 101 patent eligibility rejections (commonly called "Alice rejections" after the 2014 Alice Corp v. CLS Bank Supreme Court decision), which made it significantly harder to obtain software patents by declaring abstract ideas implemented on a computer as non-patentable.

A major strategic focus of the video is on client-server architecture. Because a U.S. patent is only enforceable within the United States, when a server is located outside the country, an enforcement gap arises. The recommended solution is to draft two sets of claims — one covering the client side and one covering the server side — so that at least one set is anchored to activity occurring within U.S. borders.

The video also offers a set of concrete writing strategies to improve patent eligibility: emphasizing how the invention improves computer performance (faster sorting, rendering, or compression), documenting resource savings (less memory, power, or bandwidth), describing any specialized hardware components, avoiding trigger language around abstract human activities (risk management, social media sharing, tax applications), and including quantitative data to demonstrate the invention cannot be performed in the human mind.

## Key Takeaways

- U.S. patents are only enforceable in the United States, so server location matters for client-server software inventions.
- Draft separate claim sets for the client side and server side to cover both potential enforcement scenarios.
- Describe in detail any ways the invention improves computer performance — speed, memory use, power consumption, or network bandwidth.
- Highlight any specialized hardware (sensors, accelerometers, custom I/O interfaces) used beyond a standard computer.
- Avoid drafting claims that read like human activities (risk management, social media, financial transactions) as these trigger Alice rejections.
- Include quantitative data (e.g., processing 3 million pixels per microsecond) to show the task cannot be performed in the human mind.
- Each patent examiner applies the Alice test slightly differently, so having detailed supporting material gives you ammunition to overcome a 101 rejection if one arises.

## Best For

This video is most useful for inventors and engineers developing software inventions who want practical drafting strategies to improve the chances of patent eligibility in the current USPTO environment.
